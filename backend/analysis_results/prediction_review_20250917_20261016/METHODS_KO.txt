현재 웹 예측모델 과거 재적용 평가 — 방법과 해석 기준
작성일: 2026-10-21 (Asia/Seoul)

1. 평가 범위
기간은 2025-09-17~2026-10-16 양 끝 날짜를 포함한 395일이다. 사용자가 지정한 날짜를 우선하였으며 정확히 365일인 구간은 아니다. 남양주1·남양주2·김해·광주·논산의 전력·연료·용수, 총 15개 계열에 대해 5,925행을 생성 완료했다. 공장·날짜·자원 키의 중복 및 실측 누락은 없다. 최종 완료 시각과 검증 결과는 manifest.json 및 validation_checks.json에 기록했다.

2. 모델과 웹 경로 재현
레지스트리에서 활성화된 v5.3.pkl을 사용한다. 모델 파일 경로·크기·SHA-256과 레지스트리, 계열별 실제 변수·분위수·앙상블 가중치는 별도 파일로 보존한다. 운영 모델의 재학습·교체 및 prediction_log 쓰기는 수행하지 않는다.
실공장 웹 API가 호출하는 predict_v5()로 각 날짜의 원본 입력, 파생 피처와 사후보정 규칙을 재현한다. 배치 서비스는 활성 SKU 입력 처리 등이 단일 서비스와 달라 평가 경로로 사용하지 않는다. 계산 시간 단축을 위해 웹 함수에서 수집한 동일 피처 행을 각 추정기에 묶어 넣고, 원래 추론 및 후처리 함수로 결과를 구성한다. 공장별 3개 날짜의 P05·P50·P95, 총 135개 값을 원래 단일 추론 경로와 대조했다. 실행 중인 웹 API와도 일반일·휴일·드리프트 보정일을 포함한 8개 표본의 96개 값을 대조했으며, 최대 절대차는 1.46×10⁻¹¹로 수치 정밀도 범위였다. API의 예측 요청은 운영 이력을 저장하지 않는다.
LightGBM·XGBoost·CatBoost의 개별 결과와 가중치는 per_model_predictions.csv에 저장한다. 이 값은 분위수 정렬·CQR·드리프트·휴일 보정 전의 원시 추정치다. 최종 예측값은 그러한 후처리를 거친 결과이므로 개별 모델 가중합과 항상 같지는 않다. 최종 결과에 대한 계열별 보정 여부는 web_results.jsonl과 일별 보정 열에 기록된다.

3. 입력 데이터와 사후평가의 의미
이 평가는 현재 모델에 과거의 실제 생산량, 관측 날씨, 재공품 실적을 넣은 사후 재적용이다. 당시 사전에 알 수 있었던 생산계획·기상예보만 사용한 예측이나, 과거 각 시점의 모델을 재현한 순차 재학습 검증은 아니다. 실제 생산량·관측 날씨를 미리 안다는 조건의 성능을 운영 사전예측 성능으로 해석하면 안 된다.
목표일 에너지 실측은 평가 정답으로만 사용하며 목표일 이전 영업일 이력으로 lag1·r7mean·이전 생산량 대비 사용량을 만든다. lag1은 직전 달력일이 아니라 직전 포함 영업일일 수 있고, r7mean은 이전 7개 포함 관측행 평균이다. 매 날짜 앞 450일 범위에서 이력을 구성한다. 당일 생산량·기온의 이동평균에는 당일 입력이 포함될 수 있다.
에너지·생산량·날씨·공장별 재공품은 실행 당시인 2026-10-21의 읽기 상태를 CSV 스냅샷으로 저장한다. 에너지·생산량·재공품 보존 범위는 원칙적으로 2024-06-24~2026-10-16이며, 날씨 스냅샷은 읽은 관측표를 보존한다. 과거 수치가 사후 수정됐을 수 있으므로 이는 당시 등록 상태를 증명하는 시점별 데이터 저장본은 아니다.
missing_production은 해당 공장·날짜의 생산실적을 찾지 못해 입력 생산량 0으로 대체했음을 뜻하며 실제 무생산과 구분한다. missing_weather_columns는 원관측의 누락 목록이다. 서비스 규칙에 따라 강수 결측은 0, 기온·습도는 과거값 우선 채움과 보완 처리, 일사·일조는 결측을 보존한다. 원자료의 누락과 최종 모델 입력값은 daily_model_inputs.csv를 함께 확인한다. 실제 사용 변수의 기준은 model_variables.csv와 모델 spec.features다. 원입력에 있는 모든 날씨 항목이 모델에 사용되는 것은 아니다.

4. 학습 구간과 비교 집단
아티팩트에는 계열별 학습 종료일·검증 종료일·학습시각이 없다. 확인된 effective_train_start는 논산 전력·연료 2021-01-01, 나머지 13개 계열 2023-01-01이다. 저장소 학습 소스의 기본 설정은 TRAIN 종료 2025-12-31, VAL 2026-01-01~03-31, TEST 2026-04-01~05-15다. evaluation_split은 이 소스 설정에 따른 참고 분류이며 아티팩트 자체가 증명한 구간은 아니다. 앞부분의 오차는 학습·가중치/CQR 보정 구간과 겹칠 수 있어 독립 검증 성능으로 제시하지 않는다.
전체 달력일(all_calendar_days), 영업일(workdays), 특이일을 제외한 영업일(regular_workdays), 비영업일(nonworkdays)을 나눠 집계한다. 원래 학습은 영업일 중심이며, 생산량이 1톤 미만이거나 최근 포함 관측 30행 중앙값의 10% 미만인 특이일을 제외하도록 되어 있다. 비영업일·저생산일의 큰 오차를 정상 가동일의 성능과 함께 평균내면 원인 판단이 달라질 수 있다.

5. 단위와 오차 정의
저장 원단위는 전력 kWh, 연료 Nm³, 용수 ton이다. 웹 화면은 해당 값을 1,000으로 나눈 표시값을 사용하므로 화면 수치와 비교할 때 단위를 맞춘다.
오차(error) = 예측 - 실측. 양수는 과대예측, 음수는 과소예측이다.
일별 APE(%) = |예측-실측| / |실측| × 100. 실측 0 또는 누락이면 정의하지 않고 비워 둔다. MAPE는 유효한 APE의 산술평균이다. 입력 스냅샷에서 실측 0은 연료 13행·용수 1행, 총 14행으로 확인됐으며 zero_actual로 표시한다.
웹 호환 APE(%) = |예측-실측| / max(|실측|, 1) × 100. 웹 호환 MAPE와 표준 MAPE는 분모 처리 차이 때문에 다를 수 있다. 0에 가까운 소비량도 MAPE를 크게 만들 수 있으므로 MAE·WAPE·편향·표본 수를 함께 본다.
WAPE(%) = 절대오차 합 / |실측| 합 × 100. bias_pct는 부호 있는 오차 합을 같은 실측 합으로 나눈 값이다. MAE와 RMSE는 각 계열의 원단위를 따른다. band_coverage_pct는 실측이 최종 P05~P95 안에 들어온 비율이다.
7일·30일 이동 MAPE는 t-N일 < 날짜 ≤ t인 달력일 이동창의 유효 APE 평균이다. 처음 6일·29일도 확보된 부분창으로 계산하며, 창 안 실측 0인 날은 평균에서 제외한다. valid_ape_7d·valid_ape_30d로 실제 분모 관측 수를 확인한다. 따라서 초반 값은 완전한 7일·30일 평균과 관측 기간이 다르다. 월별 변화는 %p 차이와 이전 달 대비 변화율을 구분한다. 2025년 9월과 2026년 10월은 부분월이어서 완전한 달과 표본 기간이 다르다.

6. 개선 후보의 해석
오차와 변수의 연관성, 계절·휴일·저생산별 성능 차이, 개별 알고리즘의 원시 성능 비교는 후속 실험을 고르는 탐색 근거다. 변수 추가나 알고리즘 교체의 효과를 입증한 결과는 아니다.
활성 아티팩트는 CDD10·CDD16, 기온 14/30일 평균, 장기연휴 직후 플래그를 실제 사용하지 않는다. 이 변수들과 CIP·세척, 라인별 가동시간, 재가동, 제품군·포장단위, 설비 변경, 냉동·보일러 부하 등의 운영 정보는 검토 후보가 될 수 있다. 후보가 실제 예측 시점에 확보 가능한지 먼저 확인한다.
알고리즘 또는 앙상블 가중치 변경, 변수 추가, 계절·휴일별 보정은 동일한 미래 검증 구간과 입력 가용 조건에서 비교해야 한다. 학습·튜닝과 분리한 시간순 검증 및 반복 검증을 거친 뒤 MAPE뿐 아니라 WAPE·편향·비영업일 성능·예측구간 포괄률까지 확인한다. 현재 결과만으로 특정 변수나 알고리즘을 최종 채택하지 않는다.

7. 결과 파일과 재현
prediction_performance_review.xlsx는 성능 요약·월별 추이·구간별 성능·최근 성능 변화·일별 예측오차·입력 파일 안내·모델 사용변수·분석 방법의 8개 시트다. 일별 입력변수 전체는 daily_model_inputs.csv에 있으며 공장(factory)·날짜(date)·자원(target)으로 daily_predictions.csv와 연결한다. 모델 사용변수 730행에는 같은 변수가 하위 모델마다 반복될 수 있다. 모델별 실제 고유 변수는 21~27개다.
Excel은 이 평가 시점의 검증된 결과를 보관한 파일이다. 원본 CSV를 바꿨을 때 모든 지표를 자동으로 다시 계산하는 입력용 모델은 아니며, 변경된 평가 결과로 재생성해야 한다. 스프레드시트 작성 도구의 대량 집계 함수 오류를 피하기 위해 검증된 지표를 저장값으로 넣었고, 지표는 원본 CSV 및 별도 독립 재검산으로 확인했다.
현재 저장소의 backend/tools/export_prediction_review.py를 기존 .venv Python으로 실행하면 모델 추론을 다시 수행한다. 이후 결과 폴더의 analyze_results.py, backend/tools/verify_prediction_review_web.py, backend/tools/finalize_prediction_review.py 순서로 보조 진단·실행 중인 웹 비교·최종 검증을 재현할 수 있다. 데이터와 모델 파일이 바뀌면 동일한 결과를 보장하지 않으므로 manifest의 모델·소스·입력 파일 해시 및 inference_environment.json을 먼저 확인한다. ZIP의 reproduce 폴더에는 해당 스크립트 사본이 있고, 재실행에는 기존 저장소·동일 모델·DB 및 현재 서비스의 원본 Excel 입력 경로가 필요하다. 2.68GB 모델 파일과 자격정보는 ZIP에 넣지 않는다.
