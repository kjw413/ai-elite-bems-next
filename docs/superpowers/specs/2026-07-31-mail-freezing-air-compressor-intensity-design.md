# 메일 냉동·공압 원단위 전체 주기 복원 설계

## 배경

2026-07-31 변경에서 에너지 원단위의 단일 기준을
`DB_에너지.xlsx` 수식 결과로 전환하면서, 별도 수식 열이 없던 냉동전력과
공압기전력 원단위가 메일 공통 지표에서 제거되었다. 이후 RawDB의 모든 공장
시트에 다음 열과 계산 수식이 추가되었다.

| RawDB 머리글 | 수식 | DB 컬럼 |
|---|---|---|
| `냉동원단위[kWh/mix-ton]` | `냉동전력량[kWh] × 1000 / 믹스생산량[kg]` | `freezing_power_per_ton_kwh` |
| `공압기원단위[kWh/mix-ton]` | `공압기[kWh] × 1000 / 믹스생산량[kg]` | `air_compressor_per_ton_kwh` |

2026-07-31 15:58 기준 실제 워크북의 남양주1·남양주2·김해·광주·논산·경산
시트에서 두 머리글, 수식, 저장 계산값이 모두 확인되었다.

## 목표

- RawDB의 냉동·공압 원단위 수식 결과를 `energy_daily`에 그대로 적재한다.
- Python에서 두 원단위를 사용량÷생산량으로 다시 계산하거나 덮어쓰지 않는다.
- 일간·주간·월간 메일의 표, 추이 차트 및 일간 즉시 점검 alert에 두 지표를
  다시 표시한다.
- 자동 동기화와 수동 업로드가 동일한 컬럼 계약과 순서를 사용하게 한다.

## 비목표

- 일반 웹 대시보드에 냉동·공압 원단위 화면을 새로 추가하지 않는다.
- RawDB 수식이나 워크북 구조를 코드에서 수정하지 않는다.
- 기존 전력·연료·용수 원단위 집계 방식을 변경하지 않는다.

## 접근 방식

RawDB → 파서 → `energy_daily` → 메일 빌더의 기존 데이터 흐름을 확장한다.
메일이 Excel을 직접 읽거나 두 원단위를 재계산하지 않는다. 이 방식은 기존
원단위의 단일 출처 원칙을 유지하고, 일간·주간·월간 메일이 같은 DB 값을
공유하게 한다.

현재 작업 트리에는 새 머리글을 충돌 없이 파싱하되 결과를 적재 대상에서
제외하는 미커밋 변경이 있다. 구현에서는 해당 부분매칭 우선순위 보호를
유지하면서 영문명을 위 표의 정식 DB 컬럼명으로 통일하고, 두 컬럼을 필수
적재 대상으로 전환한다.

## 데이터 모델과 마이그레이션

`energy_daily`에 다음 `DOUBLE NOT NULL DEFAULT 0` 컬럼을 추가한다.

1. `freezing_power_per_ton_kwh`
2. `air_compressor_per_ton_kwh`

신규 설치는 `schema.sql`이 두 컬럼을 생성한다. 기존 설치는
`_PENDING_COLUMN_MIGRATIONS`의 INFORMATION_SCHEMA 기반 멱등 마이그레이션으로
두 컬럼을 한 번만 추가한다. RawDB 및 파서의 의미 순서에 맞춰 두 컬럼을
`mix_prod_kg` 뒤, 기존 `power_per_ton_kwh` 앞에 둔다.

## 수집 및 동기화

다음 다섯 계약에 두 컬럼을 같은 순서로 추가한다.

- `excel_parser.EXPECTED_COLUMNS`와 `COLUMN_DISPLAY_NAMES`
- `excel_parser.KOR_SUBSTR_MAP`
- `daily_energy_sync_service._INSERT_COLUMNS`
- `upload_service.INSERT_COLUMNS`
- `v5_common.ENERGY_UPLOAD_TO_MODEL_COLUMNS`

부분문자열 매핑에서는 `냉동원단위`, `공압기원단위`를 각각 일반
`냉동전력량`, `공압기`보다 먼저 검사한다. 이를 통해 원단위 열이 사용량 열로
잘못 매핑되는 것을 방지한다.

두 원단위 열은 필수 열로 취급한다. 열 자체가 없는 이전 형식 파일은 업로드를
거부해 기존 DB 값을 0으로 덮어쓰지 않는다. 셀의 저장 계산값이 비어 있거나
0이면 기존 원단위 정책과 동일하게 미확정 값으로 취급하며, Python에서 대신
계산하지 않는다.

## 메일 표시와 집계

메일 공통 `INTENSITY_METRICS` 순서는 다음과 같이 복원한다.

1. 전력 원단위
2. 냉동전력 원단위
3. 공압기전력 원단위
4. 연료 원단위
5. 용수 원단위

각 새 지표는 RawDB 저장 원단위 열과 기존 사용량 열을 함께 참조한다.

| 메일 지표 | 원단위 열 | 사용량 열 |
|---|---|---|
| 냉동전력 원단위 | `freezing_power_per_ton_kwh` | `freezing_power_kwh` |
| 공압기전력 원단위 | `air_compressor_per_ton_kwh` | `air_compressor_kwh` |

단일 일자·공장은 저장 수식값을 그대로 사용한다. 여러 날짜나 공장을 합칠 때는
기존 정책과 동일하게 유효한 원단위와 믹스생산량에 대해
`SUM(원단위 × mix_prod_kg) / SUM(mix_prod_kg)`로 가중 집계한다.

공통 지표 목록을 사용하는 기존 렌더링 경로를 통해 다음 범위에 자동 반영한다.

- 일간: 공장별 스냅샷, 생산량·사용량·원단위 즉시 점검 alert
- 주간: 공장별 스냅샷, 최근 4주 추이 차트
- 월간: MTD/YTD 스냅샷, 월별 MTD 추이 차트

## 오류 처리

- RawDB 머리글 누락은 파서 검증 오류로 명시한다.
- DB 컬럼이 아직 없으면 동기화 전에 멱등 마이그레이션을 적용한다.
- 원단위 저장값 또는 믹스생산량이 유효하지 않으면 해당 집계값을 `None`으로
  유지해 메일에 `-`로 표시한다.
- 기존 메일 생성·발송 오류 처리와 로깅 방식은 변경하지 않는다.

## 테스트

1. 두 컬럼이 파서·자동 동기화·수동 업로드·모델 컬럼 매핑에 모두 등록되어
   있고 순서가 일치하는지 검증한다.
2. 부분문자열 매핑이 `공압기원단위`를 `공압기` 사용량으로 오인하지 않는지
   검증한다.
3. 신규 설치 스키마와 기존 설치 마이그레이션에 두 컬럼이 같은 순서로
   존재하는지 검증한다.
4. 저장 원단위 값의 가중평균이 사용량÷생산량 재계산 결과가 아니라 RawDB
   저장값을 사용하는지 검증한다.
5. 메일 공통 지표에 냉동·공압 원단위가 포함되고, 일간 alert가 두 사용량과
   저장 원단위를 함께 평가하는지 검증한다.
6. 관련 백엔드 전체 테스트와 메일 dry-run/preview를 실행한다.

## 배포 및 데이터 갱신

1. 멱등 DB 마이그레이션을 적용한다.
2. `sync_daily_energy_from_source(force=True)`로 현재
   `E:\DB_MIS\DB_에너지.xlsx`를 강제 재동기화한다.
3. 대표 일자의 RawDB 수식 저장값과 DB 두 컬럼을 대조한다.
4. 일간·주간·월간 메일 미리보기에서 표와 차트의 두 지표를 확인한다.

## 완료 기준

- 두 원단위가 RawDB 저장 계산값과 동일하게 DB에 적재된다.
- 일간·주간·월간 메일 전체에서 냉동·공압 원단위가 표시된다.
- 일간 즉시 점검 alert가 냉동전력과 공압기전력을 다시 평가한다.
- 기존 전력·연료·용수·폐수/용수 및 생산량 메일 지표가 회귀하지 않는다.
- 관련 자동화 테스트와 메일 생성 검증이 모두 통과한다.
